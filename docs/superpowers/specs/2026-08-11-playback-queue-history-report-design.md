# A 路线：播放队列、增量扫描与听歌报告设计

## 目标

在保持 Coriander Player 本地播放器定位的前提下，完善日常使用闭环：

1. 播放队列可编辑、可持久化，重启后恢复但不自动播放。
2. 增量扫描可靠处理新增、修改、删除和嵌套目录中的音乐文件。
3. 复用现有歌单实现受保护的“我喜欢”歌单，并在播放界面提供爱心入口。
4. 记录最近 12 个月的有效播放，用于最近历史和周/月听歌报告。

本期不新增在线服务、推荐算法、云同步、音频文件写回或独立收藏数据库。

## 已确认的用户规则

- 方案：沿用现有 JSON 文件和服务层，不引入 SQLite。
- 队列重启后恢复，但不自动启动播放。
- 队列内同一路径歌曲不重复；支持添加到队尾、添加为下一首、拖动排序、移除和清空。
- 队列恢复时自动丢弃已不存在的路径。
- “我喜欢”是受保护的系统歌单：首次启动自动创建，不能删除或改名；旧版本同名歌单会迁移合并。
- 有效播放：播放达到 30 秒或歌曲时长 50%（取先达到者）后计入历史。
- 播放历史列表只展示最近 20 条有效播放记录；同一首歌重复播放可以产生多条记录。
- 原始播放记录保留最近 12 个月；统计按歌曲、歌手、专辑聚合。
- 听歌报告展示歌曲、歌手、专辑各 Top 10，并显示总时长、有效播放次数等摘要。
- 报告按本地时间划分周/月，支持当前周、当前月和最近 12 个月的历史周期。
- 升级安装不删除 `Documents\\coriander_player`；数据格式使用版本字段并支持迁移。

## 架构

### 1. 数据与服务边界

保留现有 `playlists.json` 作为歌单存储，新增两个独立文件：

- `playback_queue.json`：队列条目路径、当前歌曲路径、上次位置和格式版本。
- `play_history.json`：有效播放事件、时间、收听时长和格式版本。

建议新增以下 Dart 服务/纯函数边界：

- `PlaylistRepository`：读取、保存、迁移歌单，并保证系统歌单唯一。
- `PlaybackQueueService`：维护队列、去重、排序、当前索引、持久化和失效路径清理。
- `PlaybackHistoryService`：管理播放会话、有效门槛、12 个月保留和最近 20 条查询。
- `ListeningReportService`：从历史事件按本地周/月聚合 Top 10 和摘要，不保存重复统计结果。
- `LibraryUpdateCoordinator`：串联 Rust 索引更新、`AudioLibrary` 重载、歌词索引刷新，以及队列/歌单/历史路径清理。

`PlaybackService` 继续负责 BASS 播放和播放模式；它通过明确的方法调用队列与历史服务，不把 JSON I/O 直接塞进播放器核心。

### 2. 数据格式

所有新增文件使用带版本号的 JSON envelope，写入采用临时文件替换并保留备份。

队列示意：

```json
{
  "version": 1,
  "items": ["D:/Music/a.flac", "D:/Music/b.flac"],
  "currentPath": "D:/Music/a.flac",
  "positionMs": 42000
}
```

历史事件示意：

```json
{
  "version": 1,
  "events": [
    {
      "path": "D:/Music/a.flac",
      "startedAt": "2026-08-11T12:30:00.000Z",
      "listenedMs": 183000,
      "qualified": true
    }
  ]
}
```

历史事件保存路径作为稳定主键；报告聚合时从当前 `AudioLibrary` 解析最新的歌曲、歌手和专辑信息，解析不到时保留路径并跳过对应名称聚合。

### 3. “我喜欢”歌单迁移

在歌单模型中增加系统歌单标记，旧 JSON 缺少该字段时默认为普通歌单。读取完成后：

1. 查找系统歌单和名称为“我喜欢”的旧歌单。
2. 将所有同名歌单的歌曲按路径合并。
3. 保留一个 `isSystem=true` 的“我喜欢”歌单。
4. UI 对系统歌单隐藏改名、删除入口。
5. 爱心按钮只切换该歌单中的当前歌曲路径，并立即保存。

扫描发现歌曲已删除时，统一从所有歌单（包括“我喜欢”）中清理该路径。

## 功能流程

### 播放队列

现有 `PlaybackService.playlist` 和 `CurrentPlaylistView` 改为由 `PlaybackQueueService` 提供可通知状态。播放入口在设置新队列时保存快照；添加、删除、排序、清空和切歌后更新持久化文件。

启动顺序为：读取应用设置 → 增量扫描并加载音乐库 → 加载歌单、队列和历史 → 清理失效路径 → 显示主界面。队列只恢复数据和当前歌曲标识，不调用 BASS 的播放启动方法。用户点击队列条目或“继续播放”后才真正加载和播放。

队列编辑使用现有播放列表视图：当前歌曲高亮，拖动手柄负责排序，行尾提供移除操作，顶部提供添加/清空操作。随机模式仍由 `PlaybackService` 维护，持久化的是当前实际队列顺序。

### 有效播放与历史

播放开始时建立内存中的播放会话，监听播放位置和状态变化。达到 30 秒或歌曲总时长 50% 时标记为有效；暂停、切歌、播放完成、停止或应用关闭时写入实际收听时长。未达到门槛的会话不写入有效历史。

加载历史时删除超过 12 个月的事件；最近历史查询返回按 `startedAt` 倒序的 20 条。历史文件写入失败只记录日志，不影响当前播放。

### 增量扫描

保留现有启动时 `updateIndex` 流程和进度页面，同时修正 Rust 扫描器：

- 递归检查已配置目录，而不是只检查目录的直接子项；
- 以规范化完整路径集合识别新增和删除；
- 对修改时间、大小或可用元数据发生变化的文件重新读取标签；
- 不再只用创建时间判断新增文件；
- 扫描结果用临时文件替换 `index.json`，失败时恢复旧索引；
- 空目录、失效目录和部分读取失败都安全处理并报告进度。

设置页新增“立即扫描”入口，共用 `LibraryUpdateCoordinator`。扫描后刷新音乐库和歌词搜索索引，再清理队列、歌单和历史中的失效路径。扫描不自动播放，不改变仍然存在的当前歌曲位置；当前歌曲文件已删除时停止播放并提示。

### 听歌报告

左侧导航新增“听歌报告”路由，但不加入默认启动页列表。报告页使用原生 Material 组件：

- 周/月和历史周期选择器；
- 总听歌时长、有效播放次数、歌曲数、歌手数摘要卡片；
- 歌曲 Top 10、歌手 Top 10、专辑 Top 10 三个排名区；
- 每行显示名次、名称、播放次数、收听时长和相对比例条；
- 点击歌曲、歌手或专辑只导航到详情页，不触发播放。

报告监听 `PlaybackHistoryService` 的变更通知；有效播放事件写入后，当前报告自动刷新。无数据周期显示空状态，不产生虚假排名。

## 兼容与错误处理

- 旧版 `playlists.json`、缺少版本字段或缺少系统标记时采用安全默认值并执行迁移。
- 新增 JSON 文件损坏时优先读取 `.bak`；备份也不可用时重置为空结构并保留错误日志。
- 所有文件写入先写 `.tmp`，成功后替换正式文件，避免中断留下半份 JSON。
- 路径失效只清理应用内记录，不删除用户音乐文件。
- 增量扫描失败时保留上一份可用 `index.json`，并允许用户稍后从设置再次扫描。
- 数据目录继续使用 `getAppDataDir()`，不依赖安装目录，因此升级、卸载程序文件和重新安装不会删除历史数据。

## 测试策略

### 单元测试

- 系统歌单创建、同名歌单合并、保护字段和旧格式迁移。
- 队列去重、添加/删除/排序/清空、JSON 往返和失效路径清理。
- 播放门槛、暂停/切歌/完成状态下的时长计算，以及 12 个月清理。
- 周/月边界、跨年、空数据和歌曲/歌手/专辑 Top 10 聚合。
- 队列、历史和歌单损坏 JSON 的备份恢复。

### Widget/集成测试

- 正在播放页和迷你播放栏爱心状态切换。
- 队列编辑、当前歌曲高亮和重启恢复但不自动播放。
- 设置页手动扫描入口和进度/错误状态。
- 听歌报告导航、周期切换、摘要和 Top 10 展示。
- 扫描完成后库、歌词索引、队列和歌单状态同步。

### 最终验证

实现过程中采用定向测试；完成后执行一次完整 Flutter 测试、改动范围分析和 `git diff --check`。不执行在线服务、音频标签写入或真实网络请求。

## 非目标

- 在线音乐搜索、在线歌词下载、推荐算法和插件市场。
- 云端同步、跨设备账户和远程统计。
- 音频文件标签编辑、批量重命名或自动整理。
- ReplayGain、无缝播放和交叉淡化等 C 路线音频引擎功能。
