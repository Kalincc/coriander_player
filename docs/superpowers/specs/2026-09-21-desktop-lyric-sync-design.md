# 桌面歌词切歌信息同步设计

## 目标

修复桌面歌词在切换歌曲后标题、歌手、专辑信息滞后一首，而歌词正文已经切换到新歌的问题。播放器端与桌面歌词组件端必须按同一顺序处理消息，并且上一首歌曲迟到的歌词行不能覆盖当前歌曲。

## 已确认的根因

播放器的 `DesktopLyricService.sendMessage` 当前直接向进程标准输入写入无分隔符 JSON；桌面歌词组件的 `DesktopLyricController` 则把 UTF-8 流的每个数据块当成一条完整 JSON 解析。Windows 管道不保证一次写入对应一次读取：多条消息可能粘连，一条消息也可能拆包。解析失败后整个数据块被丢弃，因而可能丢失 `NowPlayingChangedMessage`，但后续歌词消息仍然到达。

切歌、歌词加载和桌面歌词发送还分别通过异步回调进行，没有歌曲代次校验。快速切歌时，旧歌词行可能在新歌曲元数据之后到达。

发布脚本还从 `Ferry-200/desktop_lyric` 的固定提交构建桌面歌词，因此修复必须在构建时对与 `pubspec.lock` 一致的 `536be8df55c80a7fdf7cc20f603d3fc76a732821` 源码应用协议补丁，避免播放器和桌面歌词端版本漂移。

## 设计

### 1. 播放器端消息通道

新增轻量 FIFO 消息队列。每次发送：

1. 将消息编码为一行 JSON（末尾添加 `\\n`）；
2. 等待上一条消息写入完成；
3. 写入并 `flush` 标准输入；
4. 进程关闭或代次变化后，丢弃尚未发送的旧消息。

`PlaybackService` 在每次 `_loadAndPlay` 开始时生成请求代次，只有最新请求仍然有效时才向桌面歌词发送播放器状态和当前歌曲信息，并传递该次调用捕获的 `Audio` 快照。

### 2. 歌词代次保护

`LyricService` 在每次切换歌词来源或歌曲时递增歌词代次。异步歌词加载完成、位置变化或桌面歌词发送回调执行前都验证代次；旧代次的歌词行直接丢弃。新歌曲的元数据消息仍负责清空桌面歌词中的上一行。

### 3. 桌面歌词组件端

新增构建时补丁，将 `desktop_lyric_controller.dart` 的标准输入解析改为 `LineSplitter`：每一行独立 JSON 解析，空行忽略，单行格式错误只记录并继续处理后续消息。这样父进程的换行分帧不会受管道拆包或粘包影响。

### 4. 构建与文档

`scripts/package_windows.ps1` 在 checkout 固定桌面歌词提交后、`flutter pub get` 前应用补丁；README 的手动构建说明同步给出补丁步骤。播放器依赖版本与发布脚本使用的桌面歌词源码版本保持可追溯，不修改用户音乐库、歌词缓存或设置。

## 错误处理

- 桌面歌词进程不存在、已退出或标准输入写入失败：记录日志并清空当前队列，不影响主播放器播放。
- 补丁目标文件缺失或内容与固定提交不匹配：构建立即失败，避免发布未修复的桌面歌词组件。
- 桌面歌词收到单条畸形消息：记录错误，继续消费后续帧。

## 验收与测试

- FIFO 队列测试证明多条消息按入队顺序、逐行写出，并在第一条写入延迟时仍不乱序。
- 播放/歌词代次测试证明旧歌曲的延迟回调不会发送到桌面歌词。
- 补丁脚本测试证明目标源码被改为 `LineSplitter`，目标不匹配时失败。
