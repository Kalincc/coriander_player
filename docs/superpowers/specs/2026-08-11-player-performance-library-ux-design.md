# 播放器性能与本地库体验改进设计

## 目标

在保留现有本地歌词搜索、歌词显示、歌单、我喜欢、播放历史和听歌报告的前提下，解决当前版本的明显卡顿，并改善收藏、封面、报告可视化和播放列表语义。

本次变更包含：

1. 修复“我喜欢”爱心空心/实心显示。
2. 为歌单、听歌报告和最近播放增加专辑封面；无封面统一回退到 `app_icon.ico`。
3. 将听歌报告的排名进度线改为按播放次数归一化的横向柱状图。
4. 将搜索改为首帧加载、分批计算、逐步呈现，并取消陈旧查询，避免阻塞 UI 线程。
5. 回退播放队列到旧版纯内存语义：单曲点击只播放单曲，专辑点击建立整张专辑的播放列表。
6. 删除新版本自动/增量扫描；已有索引启动只加载，文件夹管理中的“立即扫描”执行用户主动触发的完整重建。

## 当前问题根因

- `UpdatingPage` 在每次已有索引启动时调用 Rust `updateIndex`，递归访问音乐目录；扫描结束后又启动歌词索引同步。
- `SearchResultPage` 在 `initState` 和 Enter 提交时同步遍历歌曲、艺术家、专辑和歌词。歌词索引每 25 首通知一次时，页面还会重复执行整库搜索。
- Material Symbols 的 `favorite` 与 `favorite_border` 使用同一字形，必须通过 `fill` 轴区分空心和实心。
- 歌单页、报告页和最近播放只绘制文字，没有复用已有 `Audio.cover`。
- 报告当前按播放次数排序，却用总听歌时长绘制 `LinearProgressIndicator`，排名和图形指标不一致。
- 持久播放队列在启动、播放、暂停和队列编辑时读写 JSON，并引入了拖拽、删除、清空等与旧版不同的队列语义。

## 设计

### 1. 收藏状态与封面组件

新增可复用的 `ArtworkThumbnail` 组件，接收可空的 `Future<ImageProvider?>`、尺寸和圆形/圆角参数。组件统一处理加载中、图片读取失败、空图片和 `app_icon.ico` 回退，不添加第三方依赖。

- `NowPlayingFavoriteButton` 使用 `Symbols.favorite`，liked 时 `fill: 1`，未 liked 时 `fill: 0`；点击后立即根据实际数据刷新图标。
- 歌单使用 `playlist.audios.values.last` 作为最新添加歌曲；空歌单或封面缺失显示软件 Logo。
- 普通歌单添加/移除歌曲统一通过仓库入口修改，更新 `playlistRevision` 并持久化，保证歌单封面和数量及时刷新。
- 报告歌曲和最近播放按路径映射到 `Audio`；歌手取其作品中第一首可用歌曲；专辑取该专辑作品中的第一首歌曲。

### 2. 听歌报告

保留本周、本月、近 12 个月、Top 10、摘要卡和现有详情页跳转。

每个排名区域改为原生 Flutter 横向柱状图：

- 柱长为 `rank.playCount / 本区域最大播放次数`，最高项始终满宽。
- 每行保留排名、封面、名称、播放次数和累计时长。
- 缺少元数据时仍显示排名和名称，但不可跳转，封面回退 Logo。
- 最近播放保留最多 20 条，加入封面但不触发播放。

### 3. 搜索渐进式加载

保留 `UnionSearchResult.search` 的同步 API 供纯模型测试使用，页面改用异步搜索控制器/状态：

1. 结果页先渲染搜索框、Tab 和加载指示器，不在 `initState` 同步计算整库结果。
2. 预先计算一次繁简、拼音和大小写查询形式，歌词行只执行匹配，不重复转换查询。
3. 歌曲、艺术家、专辑和歌词按固定批次扫描，每批结束通过零时长让出事件循环并发布部分结果。
4. 结果按批次更新 `ValueNotifier`，列表逐步出现；不会为每一条命中都重建整个页面。
5. 每次 Enter 生成递增 generation；旧任务、页面销毁或新查询均不能覆盖当前结果。
6. 歌词索引同步期间只显示索引进度；同步完成后最多触发一次新的搜索。

### 4. 播放队列回退

不整体回滚包含听歌历史的提交，而是恢复旧版队列语义：

- `PlaybackService.play` 直接使用调用方传入的列表替换当前内存播放列表。
- 搜索/单曲入口传入 `[audio]`；专辑详情入口传入整张专辑列表。
- 保留旧版顺序、循环、单曲循环、随机和“下一首播放”行为。
- 移除持久队列加载、保存、恢复、队尾追加、拖拽、删除和清空入口。
- `CurrentPlaylistView` 恢复只读当前播放列表；用户仍可点击列表项切换歌曲。
- `playback_queue.json` 不删除、不迁移、不读取；不会影响新版本启动。
- 播放历史的启动加载、暂停/切歌/完成记录和报告聚合全部保留。

### 5. 扫描与启动流程

#### 首次安装

没有 `index.json` 时进入欢迎页。用户选择文件夹并点击扫描，使用完整递归建库写入原子索引；成功后加载音乐库、歌单、歌词源，首次建立歌词索引并加载历史，然后进入主页面。没有选择文件夹时禁止开始扫描。

#### 已有索引启动

启动页只执行：

1. 读取并校验 `index.json`。
2. 加载 `AudioLibrary`、歌单、歌词源和已有歌词索引。
3. 加载播放历史。
4. 进入用户配置的起始页。

启动不调用任何音乐目录扫描、歌词指纹扫描或歌单/历史清理。索引损坏时显示错误和“文件夹管理”恢复入口，不自动扫描，也不静默替换为空库。

#### 文件夹管理中的“立即扫描”

“立即扫描”使用索引保存的顶层 `scanRoots` 调用完整递归建库。成功后依次重新加载音乐库、校准歌单和历史、同步歌词索引；扫描失败则保留旧索引和旧内存数据，不执行后续校准。

`AudioLibrary` 从新索引读取 `scanRoots`。旧索引没有根目录信息时仍可播放，但禁用立即扫描并提示用户重新选择文件夹后执行一次完整重建；禁止猜测公共父目录。

删除新版本增量扫描专用 Rust 函数、文件指纹逻辑和 FRB `updateIndex` ABI，保留完整建库入口及原子写入保护。

## 失败与兼容策略

- 图片读取失败只影响封面显示，不影响列表、报告或播放。
- 搜索任务出错时显示错误状态，保留已完成的部分结果，不播放任何歌曲。
- 扫描失败不 reload、不 reconcile、不刷新歌词，旧索引继续可用。
- 旧 `playback_queue.json` 保留在磁盘，版本不会读取它。
- 手动完整扫描可能比旧增量扫描耗时，但只在用户点击“立即扫描”时执行，显示流式进度且防止重复点击。

## 验证范围

只保留必要的关键验证：

- 爱心状态和封面回退组件测试。
- 歌单最新封面、报告封面/柱状图、最近 20 条测试。
- 搜索首帧 loading、渐进结果、连续查询取消和歌词索引完成后单次刷新测试。
- 单曲/专辑队列替换、随机恢复、下一首和历史记录回归测试。
- 启动只加载不扫描、损坏索引错误态、手动完整扫描成功/失败顺序和旧索引无 roots 保护测试。
- 一次相关 Flutter 测试集合、一次完整 `flutter test --no-pub`、`dart analyze` 和 `git diff --check`。
- Rust/FRB 绑定在 GitHub Actions 上执行编译检查；本机未安装 Cargo 时不额外安装工具链。
