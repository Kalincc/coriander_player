# Coriander Player 本地歌词搜索、歌词居中与专辑艺术家筛选设计

**日期：** 2026-07-30

**状态：** 用户已确认

**范围：** Windows 版 Coriander Player；不包含在线歌词搜索、播放内核修改或桌面歌词程序修改

## 1. 目标

本次改动包含三个相互独立、可分别验证的功能：

1. 现有搜索增加本地歌词内容搜索。搜索结果按歌曲分组，显示该歌曲全部命中的歌词句；点击结果只定位到音乐列表中的歌曲，不播放，也不改变播放进度或播放队列。
2. 正在播放页面的当前歌词行在所有窗口尺寸下位于歌词可视区域的垂直中心。
3. 专辑页面顶部增加艺术家筛选器，可在“无分类”和单个艺术家之间切换，并支持在艺术家选择器内搜索名称。

## 2. 非目标

- 不搜索、下载或预缓存在线歌词。
- 不修改用户为某首歌曲选择的在线歌词来源。
- 不修改 BASS、WASAPI、播放队列或播放模式。
- 不修改独立的 `desktop_lyric` 项目。
- 不建立实时文件系统监听；运行期间外部修改的歌词在下次启动或音乐库更新时检测。
- 不把艺术家筛选状态写入 `app_preference.json`。
- 不重构与本次功能无关的音乐库、导航或页面组件。

## 3. 方案选择

歌词搜索采用独立、持久化、增量更新的索引。拒绝以下两种方案：

- 每次搜索逐个读取全部歌曲歌词：实现简单，但大曲库搜索延迟和磁盘负载不可接受。
- 每次启动只建立内存索引：当前会话搜索快，但每次重启都要重复读取所有歌词。

选定方案将歌词索引写入应用数据目录下的 `lyric_search_index.json`。该文件与现有 `index.json` 分离，不改变 Rust 音乐索引结构，也不重复保存歌曲标题、艺术家和专辑信息。

## 4. 架构与模块边界

### 4.1 `LyricSearchIndex`

新增独立的 Dart 服务，负责：

- 加载和校验歌词搜索索引；
- 根据现有 `AudioLibrary` 进行新增、修改和删除检测；
- 调用项目现有的本地歌词读取与 LRC 解析能力；
- 控制并发读取数量；
- 原子化保存索引；
- 提供构建进度、就绪状态和搜索接口。

该服务不负责绘制界面、导航或播放。

### 4.2 索引数据模型

每首歌曲的记录至少包含：

- 音乐文件绝对路径；
- 音频文件修改时间；
- 同名外挂 LRC 的路径、存在状态和修改时间；
- 解析后的歌词行列表；
- 索引格式版本。

每行歌词包含：

- 开始时间，单位为毫秒；
- 用于展示的原始文本；
- 用于不区分英文字母大小写搜索的规范化文本。

歌曲标题、艺术家、专辑和封面不写入歌词索引。加载索引后，通过绝对路径关联当前 `AudioLibrary` 中的 `Audio` 对象。无法关联的旧记录会被删除。

### 4.3 搜索结果模型

`UnionSearchResult` 在现有音乐、艺术家和专辑结果之外增加歌词结果。歌词结果按歌曲分组，每组包含：

- 对应 `Audio`；
- 所有命中的歌词行；
- 每行的开始时间和文本。

单独的 `LyricSearchResultTile` 负责歌曲信息、时间、歌词文本、命中词高亮和定位操作，避免继续扩大搜索结果页面的职责。

### 4.4 当前歌词定位

`VerticalLyricView` 内抽取统一的“滚动到当前歌词行”方法。初始化、自然换行、拖动进度、点击歌词、字号变化和窗口尺寸变化均通过同一个方法计算目标位置。

中心目标是当前歌词 tile 的完整边界，包括翻译和自动换行后的高度，而不是只对齐第一行文字。现有首尾填充结构继续保证第一句和最后一句也能滚动到中心。

### 4.5 专辑艺术家筛选

专辑页持有当前选择的艺术家状态，并根据该状态派生传给 `UniPage<Album>` 的列表：

- “无分类”：`AudioLibrary.instance.albumCollection.values`；
- 指定艺术家：该艺术家关联的专辑集合。

新增专辑页专用的艺术家选择器组件，负责艺术家名称搜索和单选。筛选不扩展为通用筛选框架，避免与本次需求无关的抽象。

## 5. 歌词索引生命周期

### 5.1 启动

音乐库完成加载后读取 `lyric_search_index.json`。已有有效记录立即可用于搜索，同时在后台执行增量校验。

### 5.2 首次构建

不存在有效索引时，在后台处理音乐库中的全部歌曲。构建不得阻塞播放、切歌或页面导航。读取任务限制并发度，避免一次性打开大量文件。

### 5.3 增量更新

下列情况重新读取单首歌曲的本地歌词：

- 歌曲刚加入音乐库；
- 音频文件修改时间改变；
- 同名外挂 LRC 新增、删除或修改；
- 索引记录版本过旧或字段不完整。

歌曲从音乐库删除时，其歌词索引记录也删除。未变化歌曲不重复读取。

### 5.4 更新触发点

- 应用启动并完成音乐库加载后；
- 用户执行音乐库更新并重新加载 `AudioLibrary` 后。

不增加常驻文件系统监听。播放器运行期间由外部程序修改的 LRC，最迟在下次启动或音乐库更新时生效。

### 5.5 持久化安全

索引先写入同目录临时文件，完整写入成功后再替换正式文件。索引不存在、损坏或版本不兼容时自动重新构建。重建失败不能影响播放器正常启动和播放。

## 6. 搜索行为

### 6.1 匹配规则

- 搜索词去除首尾空格；空搜索词不执行查询。
- 使用不区分英文字母大小写的连续子串匹配。
- 中文、日文及其他字符按原字符匹配。
- 空白歌词行不进入搜索结果。
- 相同歌曲中开始时间和文本均相同的重复命中只保留一次。
- 同一歌曲的命中歌词按开始时间升序排列。
- 不使用在线歌词，也不因当前默认歌词来源是在线来源而改变索引内容。

### 6.2 搜索结果页面

搜索框提示改为“搜索歌曲、艺术家、专辑、歌词”。标签顺序为：

`所有 | 音乐 | 歌词 | 艺术家 | 专辑`

“所有”标签按音乐、歌词、艺术家、专辑的顺序显示非空分区。“歌词”标签只显示歌词匹配。

每个歌词结果组显示歌曲封面、歌曲名、艺术家、专辑，以及该歌曲全部命中的歌词句。每句显示 `mm:ss` 时间和歌词文本，搜索词使用当前主题色高亮。不折叠或截断命中句集合。

点击歌曲区域、歌词行或定位按钮均复用现有音乐页面定位路由：进入音乐页面并滚动到对应歌曲。该操作不得调用播放服务，不得改变当前歌曲、队列或播放位置。

### 6.3 索引构建期间

- 页面显示“正在建立本地歌词索引：已处理 X/Y”。
- 歌曲名、艺术家和专辑结果立即正常显示。
- 可以显示当前已完成索引部分的歌词结果。
- 索引完成后，仅当搜索词仍未改变时自动重新执行该查询。
- 旧查询的异步结果不得覆盖更新后的搜索词。

### 6.4 空状态

- 没有歌词匹配时，“歌词”标签显示明确空状态。
- “所有”标签中歌词结果为空时不显示空的歌词分区。
- 索引构建失败时提供非阻塞提示，其他搜索类型保持可用。

## 7. 当前歌词居中行为

当前歌词 tile 的几何中心应与歌词可视区域的垂直中心对齐。歌词可视区域不包含底部播放进度条和控制区。

重新定位触发条件：

- 打开正在播放页面；
- 自然播放进入下一句；
- 用户拖动播放进度；
- 用户点击歌词跳转；
- 修改歌词字号或对齐方式；
- 窗口高度变化；
- 宽屏和窄屏布局切换。

保留现有 300 ms 滚动时长和 `Curves.fastOutSlowIn`。用户手动滚动查看上下文时不立即强制归位；进入下一句后恢复自动居中。若目标 tile 尚未挂载，则在安全的后续帧重试或等待下一次有效触发，不访问失效的 `BuildContext`。

## 8. 专辑艺术家筛选行为

专辑页顶部工具栏新增筛选按钮，与现有排序方法、升降序和内容视图按钮并列。默认文案为“艺术家：无分类”。

点击按钮打开艺术家选择器：

- 顶部提供名称搜索框；
- 第一项固定为“无分类”；
- 其余艺术家按名称升序排列；
- 输入时即时过滤艺术家列表；
- 一次只能选择一位艺术家；
- 选择后关闭选择器并更新按钮文案。

筛选后：

- 只显示该艺术家关联的专辑；
- 页面副标题显示“该艺术家的 N 张专辑”；
- 没有专辑时显示空状态；
- 现有标题/作品数量排序、升降序和列表/表格切换继续作用于筛选结果。

筛选状态只保留在当前运行内，不写入任何配置文件。应用每次启动时均恢复“无分类”。

## 9. 错误处理

- 单首歌曲或 LRC 无法读取时记录日志并跳过，不中断整批构建。
- 构建过程中音乐或歌词文件被移动、删除时安全跳过，并在本轮或下一轮同步中清理记录。
- 损坏或无法解析的歌词不产生搜索记录。
- 损坏、缺失或版本不兼容的索引自动重建。
- 索引保存失败保留上一个有效文件，并继续使用内存中的可用数据。
- 当前艺术家在音乐库更新后不存在时，筛选自动回到“无分类”。
- 居中滚动在控制器未挂载、目标不存在或页面销毁后不得抛出异常。

## 10. 测试策略

### 10.1 歌词索引单元测试

- 首次创建索引；
- 未修改歌曲不重复读取；
- 音频修改后重新索引；
- 外挂 LRC 新增、修改和删除；
- 歌曲删除后清理记录；
- 损坏 JSON 自动恢复；
- 无歌词、损坏歌词和不可访问文件不阻断构建；
- 临时文件写入失败时保留旧索引。

测试通过依赖注入的歌词读取器、文件状态读取器和索引存储，避免单元测试依赖真实音乐文件或 Rust FFI。

### 10.2 搜索单元与组件测试

- 英文大小写和中文包含匹配；
- 一首歌多句命中时只形成一个分组；
- 重复行去重并按时间排序；
- “所有”和“歌词”标签内容正确；
- 全部命中句均展示；
- 点击歌曲、歌词行和定位按钮只触发定位导航；
- 索引完成后只刷新未变化的查询；
- 空结果、构建中和构建失败状态正确。

### 10.3 歌词居中组件测试

- 单行歌词；
- 带翻译歌词；
- 长文本自动换行；
- 不同窗口高度和字号；
- 初始化、自然换行、进度跳转和窗口缩放；
- 当前 tile 中心与歌词视口中心在允许的像素误差内一致。

### 10.4 专辑筛选组件测试

- “无分类”显示全部专辑；
- 选择单个艺术家；
- 艺术家名称搜索；
- 筛选后排序和视图切换仍正确；
- 音乐库更新后选中艺术家不存在时恢复默认；
- 序列化偏好中不存在艺术家筛选字段。

### 10.5 最终验证

- `flutter analyze`；
- 全部 Flutter 测试；
- Rust 检查；
- Windows Release 构建；
- 使用外挂 LRC、内嵌歌词、多句命中、多艺术家专辑和不同窗口尺寸进行手动回归。

## 11. 实施顺序与工作量

1. 持久化增量歌词索引：2–4 个开发工作日。
2. 搜索页面和歌词结果组件：1–2 个开发工作日。
3. 当前歌词居中：0.5–1 个开发工作日。
4. 专辑艺术家筛选：1–2 个开发工作日。
5. 自动测试、Windows 构建和手动回归：1–2 个开发工作日。

总工作量预计为 6–10 个开发工作日。三项功能应分别完成、测试和提交，最后再进行整体回归。

## 12. 验收标准

- 本地外挂和内嵌歌词可通过现有搜索入口查询，在线歌词不会被请求或纳入结果。
- 一首歌只显示一个歌词结果组，组内展示全部命中句。
- 点击歌词结果只定位音乐列表中的歌曲，不播放、不跳转播放进度、不改变队列。
- 首次索引在后台完成并显示进度；后续只更新发生变化的歌曲或 LRC。
- 当前歌词在宽屏、窄屏、不同字号、翻译和换行情况下均位于歌词视口垂直中心。
- 专辑页可选择“无分类”或单个艺术家，艺术家选择器支持名称搜索。
- 专辑筛选不影响现有排序和视图切换，且重启后恢复“无分类”。
- 索引损坏、单文件读取失败和文件变化不会导致播放器无法启动或搜索页面崩溃。
