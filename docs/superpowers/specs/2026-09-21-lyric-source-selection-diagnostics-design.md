# 选择歌词源与在线搜索诊断设计

## 状态

已获用户确认，进入实现。

## 目标

解决“在线歌词可以正常显示，但打开选择窗口没有候选”的歧义，并把菜单文案从“指定默认歌词”改为“选择歌词源”。

## 设计

1. 保留现有 `uniSearch(Audio)` 返回候选列表的接口，避免影响自动匹配和既有测试。
2. 新增带诊断信息的搜索报告接口。报告包含每个在线来源的状态、有效候选数量和可展示的失败原因。
3. 选择窗口使用报告接口，并在实时搜索结果前加入同一首歌的有效歌词缓存候选。缓存候选带有“已缓存”标识，实时候选仍可继续选择。
4. 缓存候选通过现有缓存键还原来源 ID/哈希，并复用 `getOnlineLyric` 读取正文，不写入音频标签。
5. 来源状态至少区分“已找到候选”“无有效结果”“搜索失败”；有候选但补充查询失败时显示部分成功和错误提示。
6. 空结果时显示明确的说明，而不是空白列表；来源状态用紧凑标签呈现，详细错误通过提示文本可见。

## 数据流

`选择歌词源` → `searchOnlineLyrics` → 并行查询 QQ/酷狗/网易云 → 合并实时候选与有效缓存候选 → 显示来源状态和候选 → 点击候选后沿用现有逐曲来源持久化。

缓存仅用于候选展示和正文复用；自动播放路径的缓存优先和多候选回退逻辑保持不变。

## 测试与验收

- 一个来源抛出异常时，报告保留其他来源的候选，并记录失败状态和原因。
- 实时搜索为空但缓存有有效歌词时，报告返回缓存候选并标记为已缓存。
- 无候选时，窗口显示“没有找到可用歌词候选”和各来源状态。
- 菜单和对话框标题显示“选择歌词源”，代码中不再显示旧的“指定默认歌词”文案。
- 现有匹配器、缓存、歌词预览和来源选择测试保持通过。
