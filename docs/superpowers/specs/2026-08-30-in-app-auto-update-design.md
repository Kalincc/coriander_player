# 应用内一键自动更新设计

## 目标

为 Coriander Player 安装版增加应用内一键更新能力。用户在“设置 → 检查更新”发现新版本后，只确认一次，播放器便自动完成下载安装包、校验、退出、原位置静默覆盖安装和重新启动。

本功能计划进入 `v1.5.1-kalin.10`。由于 `v1.5.1-kalin.9` 尚未包含更新器，用户需要手动覆盖安装 `.10` 一次；从 `.10` 开始，后续正式版本可在软件内自动升级。`.9 → .10` 使用相同的安装器 `AppId`，不需要卸载 `.9`。

## 当前基础

- `CheckForUpdate` 已通过 GitHub API 读取 `Kalincc/coriander_player` 的 Release，并使用 `ForkReleaseVersion` 比较版本。
- GitHub Actions 已为正式标签发布固定命名的 `Setup.exe`、`Portable.zip` 和 `SHA256SUMS.txt`。
- Inno Setup 安装器使用固定 `AppId`，并把安装目录记录在当前用户注册表中。
- 用户歌单、音乐库索引、播放历史、听歌报告和设置位于 `Documents\coriander_player`，不在安装目录中。

## 非目标

首版不实现以下能力：

- 启动时自动检查或后台下载。
- 强制更新、测试版通道或多更新源。
- 断点续传和差分更新。
- Portable 版原地自动替换。
- 独立更新助手程序。
- 代码签名证书采购与签名流程。

## 用户流程

保留“设置 → 检查更新”的手动入口。发现正式新版本后，更新窗口展示版本号、发布时间和 Release 说明，并提供“暂不更新”和“立即更新”。

点击“立即更新”后，窗口依次展示以下状态：

1. `正在下载安装包…… N%`
2. `正在验证安装包……`
3. `正在准备安装……`
4. `播放器即将关闭并完成升级`

下载阶段允许取消。取消后终止请求、删除未完成的 `.part` 文件并保持播放器运行。进入校验和安装准备阶段后禁用重复操作。

只有安装器进程成功启动后，播放器才执行最终关闭。安装器在原安装目录静默覆盖文件，成功后自动重新打开播放器。

Portable 版发现更新时不显示“立即更新”，改为“下载新版本”，并明确提示 Portable 版不能自动覆盖。该入口打开对应 Release 页面，不在后台安装另一份程序。

## 安装版识别

应用通过 Windows 当前用户注册表读取固定 Inno Setup `AppId` 的卸载记录，并验证注册的安装目录与当前可执行文件目录一致。只有两项同时满足时才启用自动更新：

- 注册表中的安装记录属于 `AppId {B1A7B3E9-42C5-4AE5-8B3D-79078C73D4F2}`。
- 记录的安装目录规范化后与当前 `coriander_player.exe` 所在目录相同。

记录缺失、无法读取或目录不一致均按 Portable 版处理。不得仅根据默认路径或文件名猜测安装类型，避免更新另一处已安装副本。

## 组件边界

### `UpdateService`

负责获取、筛选和解释 Release：

- 仅读取 `Kalincc/coriander_player`。
- 跳过 draft 和 prerelease。
- 使用现有 `ForkReleaseVersion` 比较版本。
- 为目标版本精确选择 `Coriander.Player.<version>.Setup.exe` 和 `SHA256SUMS.txt`。
- 不执行或解析 Release 正文中的命令和下载链接。

组件返回与界面无关的更新描述，包括版本、说明、安装包 URL、校验文件 URL、文件名和发布时间。

### `UpdateDownloader`

负责网络下载和完整性验证：

- 使用 GitHub 返回的 HTTPS Release asset 地址。
- 以流式方式写入系统临时目录，避免将整个安装包读入内存。
- 下载期间使用 `.part` 后缀；完整完成后再改为正式文件名。
- 发布字节数和总大小供界面显示进度。
- 支持取消并清理不完整文件。
- 解析 `SHA256SUMS.txt` 中与目标安装包精确同名的条目。
- 使用 SHA-256 校验安装包；缺少条目、格式错误或哈希不匹配均视为失败。

`crypto` 应作为直接依赖声明，不能依赖其他包间接带入。

### `InstallEnvironment`

负责读取并验证安装器注册信息，对外只返回“当前是否为可自动升级的安装版”和必要的诊断原因。Windows 注册表访问放在现有原生边界中，不把注册表细节散落到界面代码。

### `UpdateInstaller`

负责启动已验证的安装包。启动参数使用 Inno Setup 静默模式、禁止自动重启 Windows、允许关闭占用安装文件的应用，并携带专用的应用内更新参数。安装路径由固定 `AppId` 的现有安装记录决定，不由播放器传入或猜测。

安装器脚本区分两种运行方式：

- 普通手动安装继续显示向导和安装结束后的启动选项。
- 携带应用内更新参数的静默安装在成功后直接启动 `{app}\coriander_player.exe`，不显示向导。

安装器写入独立日志文件。安装未完成时不得执行重启播放器步骤。

### `ApplicationShutdown`

统一封装正常退出流程，供标题栏退出按钮和更新流程复用：

1. 停止播放并释放 BASS/WASAPI。
2. 结束桌面歌词组件。
3. 保存歌单、歌词来源、应用设置和偏好。
4. 注销全局快捷键。
5. 关闭窗口和进程。

更新流程先完成所有可等待的保存操作，再启动安装器。任何必要保存失败均取消安装并保持播放器运行。安装器启动失败时同样不得关闭播放器。

## 数据流与状态

更新界面只消费一个明确的状态模型：

- `idle`
- `checking`
- `available`
- `downloading(progress)`
- `verifying`
- `preparingInstall`
- `failed(message, canRetry)`
- `cancelled`

成功启动安装器后应用即进入退出流程，不需要维持后续界面状态。状态转换由更新协调单元管理，Widget 不直接执行网络、哈希、注册表或进程操作。

同一时间只允许一个更新任务。关闭更新窗口或取消操作必须使旧下载结果失效，旧异步任务不能覆盖新的界面状态。

## 失败处理

- GitHub API 或下载网络异常：保留播放器，显示中文原因并允许重试。
- Release 缺少精确匹配的安装包或校验文件：停止自动更新并提供 Release 页面入口。
- 临时目录不可写或磁盘空间不足：停止下载并显示系统错误摘要。
- 用户取消：中止下载并删除 `.part` 文件。
- SHA-256 缺失、解析失败或不匹配：删除安装包，不启动任何进程。
- 当前不是可验证的安装版：只提供 Portable 下载入口。
- 退出前数据保存失败：不启动安装器。
- 安装器进程创建失败：保持播放器运行，并保留已校验安装包供重试。
- 安装器执行失败：不启动新版本；保留安装日志和已校验安装包，供用户手动重试和诊断。

底层异常写入现有日志，界面显示简短、可行动的中文说明，不直接暴露英文堆栈。

## 安全边界

- 只信任固定仓库的正式 Release 和精确资产名称。
- 所有下载地址必须是 HTTPS。
- 安装包必须通过同一 Release 的 SHA-256 清单校验。
- 校验和能够发现传输损坏或资产不一致，但不能替代发布者数字签名；仓库账户或 Release 同时被篡改时，清单本身也不可信。
- 安装器继续使用 `PrivilegesRequired=lowest`，不主动申请管理员权限。
- 不读取、不迁移和不删除 `Documents\coriander_player` 中的用户数据。

## 测试与验证

### 单元测试

- 版本比较、正式 Release 筛选以及 draft/prerelease 排除。
- 精确安装包选择，拒绝名称近似或版本不匹配的资产。
- `SHA256SUMS.txt` 的正确、缺失、格式错误和不匹配情况。
- 下载进度、取消、断网和 `.part` 文件清理。
- 注册表记录存在、缺失、目录匹配和目录不匹配。
- 安装器启动失败时不进入退出流程。
- 数据保存失败时不启动安装器。
- 并发点击、窗口关闭和陈旧异步任务保护。

### Widget 测试

- 更新窗口从可用版本到下载、校验和准备安装的状态展示。
- 下载阶段取消按钮有效，其余阶段禁用重复操作。
- 安装版显示“立即更新”，Portable 版显示“下载新版本”。
- 各类失败显示对应中文操作入口。

### 发布与人工验证

- GitHub Actions 保持完整 Flutter 测试、静态分析、Rust 检查和安装器烟雾测试。
- 安装器测试验证固定 `AppId`、静默覆盖、用户选择的原目录保留以及只有应用内更新参数才自动重启播放器。
- `.10` 发布前使用可注入的假 Release、下载器和安装器启动器验证完整状态流，不依赖真实更新覆盖开发环境。
- 用户手动覆盖安装 `.10` 后，再通过下一版测试 Release 或 `.11` 正式版验证 `.10 → .11` 的真实端到端自动更新。

## 验收标准

- 安装版用户发现新正式版本后，只需点击一次“立即更新”。
- 下载过程可见且可以取消。
- 未通过 SHA-256 校验的文件绝不执行。
- 失败不会提前关闭当前播放器或损坏用户数据。
- 成功更新沿用当前安装目录，并自动启动新版本。
- Portable 版不会静默安装出第二份 Coriander Player。
- `.9 → .10` 无需卸载；`.10` 之后可以通过应用内流程升级。
