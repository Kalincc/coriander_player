# 歌词核心增强 B1 设计

## 状态

已确认设计，等待实现计划。

## 背景

Coriander Player 已支持本地 LRC、KRC、QRC、Apple/iTunes TTML 歌词，也支持本地歌词搜索、在线歌词匹配、歌词来源选择和桌面歌词。当前歌词搜索主要按原始文本进行大小写不敏感匹配；歌词显示已有字体、对齐和翻译字号控制，但没有统一的歌词时间偏移开关，繁体歌词也不能稳定通过简体或拼音查询。

本期目标是在不修改音频文件、不下载或编辑歌词的前提下，改善歌词检索和显示同步体验。

## 目标

1. 简体、繁体和完整拼音可以互相搜索本地歌词。
2. 歌词翻译文本可以参与本地歌词搜索。
3. 搜索结果继续展示音频文件中的原始歌词内容，并保持当前“不自动播放”的行为。
4. 主界面歌词和桌面歌词支持统一的提前/延后调整。
5. 可以显示或隐藏歌词翻译，且所有歌词视图使用同一个设置。
6. 保留现有本地/在线优先级和单曲指定歌词来源行为。
7. 旧版本设置和歌词索引能够自动兼容或重建。

## 非目标

本期不包含以下内容：

- 拼音首字母搜索。
- 每首歌曲独立的歌词偏移。
- 在线歌词下载、缓存和版本管理。
- 歌词时间轴编辑或校准。
- 将歌词写入 MP3、FLAC、MP4 等音频文件。
- 批量歌词处理。

## 用户体验

### 本地歌词搜索

搜索输入会建立以下匹配形式：

- 原始文本（大小写不敏感）。
- 简体中文文本。
- 繁体中文文本。
- 完整拼音文本。
- 主歌词和翻译文本。

搜索结果显示原始歌词文本；如果命中翻译，也可以在同一条结果中显示对应的原文和翻译。搜索结果仍只提供歌曲定位，不自动播放歌曲。

首期不启用拼音首字母匹配，避免短查询产生大量误命中。

### 歌词时间偏移

歌词控制菜单增加偏移控制：

- 调整范围约为 `-10000ms` 至 `+10000ms`。
- `+` 表示歌词延后，`-` 表示歌词提前。
- 提供 `100ms` 步进的增加、减少和重置操作。
- 默认值为 `0ms`。

偏移只改变歌词显示和当前行计算，不修改歌词对象的原始时间、不改变搜索结果时间戳，也不写入音频文件。

### 翻译显示

当当前歌词存在翻译时，歌词控制菜单显示“显示/隐藏翻译”。没有翻译时不显示无效控制。该开关同时影响：

- 正在播放页面的纵向歌词。
- 标题栏或迷你区域的横向歌词。
- 桌面歌词。
- 歌词来源预览中的当前歌词文本。

默认保持现有行为，即显示翻译。

### 歌词来源

继续保留以下现有行为：

- 全局本地优先或在线优先。
- 每首歌曲指定默认歌词来源。
- 播放页面手动切换本地或在线歌词。

B1 不新增歌词来源，也不改变现有在线匹配服务。

## 架构和数据流

### 搜索标准化

新增纯函数式歌词搜索标准化层，由索引建立和查询两端共同使用。标准化层负责文本清理、大小写统一、简繁转换和完整拼音生成，但不修改展示文本。

`LyricSearchLine` 保留原始 `text`，并增加可选的翻译文本和预计算搜索形式。歌词索引格式升级到版本 `2`，避免每次输入查询时重复转换整套音乐库。旧版本索引加载时清空并由现有后台同步流程重建，重建期间继续显示进度和错误状态。

索引建立时：

1. 从当前 `Lyric` 提取主歌词和翻译。
2. 使用搜索标准化层生成原文、简体、繁体和完整拼音形式。
3. 保存原始文本、翻译文本、开始时间和搜索形式。

查询时：

1. 对用户输入执行同一标准化流程。
2. 对索引中的搜索形式执行包含匹配。
3. 按歌曲分组并按原始开始时间排序。
4. 返回原始主歌词和翻译用于结果展示。

现有 LRC 使用的 `┃` 翻译分隔格式继续兼容；显示层负责拆分，不改变原始歌词解析格式。KRC、QRC、TTML 中已有的翻译字段继续沿用。

### 歌词显示设置

扩展现有 `NowPlayingPagePreference`，增加：

```text
lyricOffsetMs: int = 0
showTranslation: bool = true
```

设置通过现有偏好设置 JSON 保存。读取旧设置时，缺失字段使用默认值，不需要迁移脚本。

### 统一时间计算

新增只读的歌词时间计算辅助层，不直接修改 `LyricLine.start`、`SyncLyricLine.length` 或歌词单词时间。辅助层提供：

- 根据音频播放位置和偏移计算歌词时间位置。
- 根据调整后的时间定位当前歌词行。
- 根据调整后的时间计算逐字高亮进度。

`LyricService`、主界面歌词视图、横向歌词视图和桌面歌词服务都使用同一套计算规则，从而避免不同视图出现偏移不一致。

### 歌词控制

在现有 `LyricViewController` 中增加偏移和翻译显示状态，并由现有 `LyricViewControls` 提供操作入口。控制器只负责状态和持久化，时间计算由独立辅助层负责，避免 UI 组件重复实现偏移逻辑。

## 异常处理和兼容性

- 空搜索词返回空结果。
- 某个音频歌词读取失败时跳过该文件，其余索引继续建立。
- 索引 JSON 损坏或版本过旧时清空并重建，不删除音乐文件、歌单或歌词来源配置。
- 偏移值始终限制在允许范围内；调整后小于零的歌词时间按零处理。
- 没有歌词时，偏移和翻译控制不产生副作用。
- 没有翻译时不显示翻译按钮，也不改变主歌词布局。
- 桌面歌词不可用时，主播放器歌词功能不受影响。
- 偏移为零且翻译开关打开时，行为与 B1 之前保持一致。

## 测试和验收

### 单元测试

- 简体查询命中繁体歌词。
- 繁体查询命中简体歌词。
- 完整拼音查询命中中文歌词。
- 翻译文本可以命中对应歌曲。
- 原始歌词和翻译内容正确序列化、反序列化。
- 索引版本升级后旧索引可以触发重建。
- 正偏移、负偏移和重置后的当前行计算正确。
- 逐字歌词偏移后高亮进度正确。
- 旧偏好设置缺少新字段时使用默认值。

### 组件测试

- 搜索结果仍显示歌曲信息和命中歌词片段，不触发播放。
- 翻译开关可以显示和隐藏翻译。
- 没有翻译时不显示无效控制。
- 偏移增加、减少和重置按钮更新设置。

### 验收标准

1. 输入“爱情讯息”可以找到歌词中的“愛情訊息”。
2. 输入完整拼音可以找到对应中文歌词。
3. 搜索结果仍显示文件中的原始歌词，不自动播放。
4. 将偏移设置为 `+1000ms` 后，当前歌词比原来晚一秒切换。
5. 主界面和桌面歌词使用同一偏移。
6. 隐藏翻译后各歌词视图都不再显示翻译。
7. TTML、LRC、KRC、QRC 现有解析和显示测试不回归失败。
8. 不产生对音频文件的写操作。

## 发布和迁移

B1 实现完成后，歌词索引格式版本提升为 `2`。用户第一次启动新版本时可能需要重新建立本地歌词索引；该过程使用现有进度提示，不要求重新选择音乐文件夹。偏好设置采用字段缺省兼容，不影响既有设置。
