# 专辑分组、听歌报告柱状图与独占模式恢复设计

## 目标

在不引入新运行时依赖的前提下完成四项体验改进：

- 将正在播放页的“我喜欢”爱心提示改为中文。
- 让专辑页默认按艺术家分组，并让现有排序只作用于组内专辑。
- 将听歌报告的歌曲、歌手和专辑 Top 10 改为按累计听歌时长展示的纵向柱状图。
- 修复 WASAPI 独占模式遇到设备不支持的音频格式后卡住且无法继续播放的问题。

本次先完成代码与必要验证，不立即发布新版本。若后续发布，使用新版本 `v1.5.1-kalin.9`，不得覆盖 `v1.5.1-kalin.8`。

## 已确认的现状与根因

### 独占模式

用户使用 Sony WH-1000XM4 随附的 3.5 mm 音频线，连接联想拯救者 R7000 2021 的 3.5 mm 耳机接口。Windows 当前输出链路包含 Realtek High Definition Audio。

出现问题时播放的 `银泰.m4a` 是 ALAC、96 kHz、24-bit、双声道。当前 `BassPlayer` 在启用独占模式时：

1. 释放普通播放流。
2. 使用 `BASS_SAMPLE_FLOAT | BASS_STREAM_DECODE` 重新创建解码流。
3. 使用 `BASS_WASAPI_Init(-1, 0, 0, EXCLUSIVE | EVENT, ...)` 将该解码流交给默认 WASAPI 输出端点。

WASAPI 独占模式不会替应用执行采样率转换；设备必须直接支持解码流格式。当前 Realtek 输出端点不支持这首歌所请求的独占格式，因此返回 `BASS_ERROR_FORMAT`。

现有异常处理只把 `wasapiExclusive` 布尔值改回原值，没有把已经创建的 `BASS_STREAM_DECODE` 流重建为普通播放流。该流不能通过 `BASS_ChannelStart` 直接播放，因此独占初始化失败后播放器会停留在不可播放状态。这是报错后卡住的直接原因。

### 专辑数据关系

`AudioLibrary` 已将艺术家繁简名称归一化，并在 `Artist.albumsMap` 与 `Album.artistsMap` 之间建立双向关系。合作专辑可能属于多位艺术家；现有按艺术家筛选行为会在每位相关艺术家下返回该专辑。

### 听歌报告

报告当前按播放次数排序，并使用横向进度条表示播放次数。每个排名项已经包含累计听歌时长、播放次数、可导航元数据和封面来源。

## 设计

### 1. 爱心中文提示

`NowPlayingFavoriteButton` 保持现有空心/实心图标和点击行为，仅替换 Tooltip：

- 未收藏：`添加到“我喜欢”`
- 已收藏：`从“我喜欢”移除`

没有当前歌曲时按钮仍保持禁用。

### 2. 专辑页按艺术家分组

专辑页保留三种查看方式：

- 默认“按艺术家分类”：显示所有艺术家分组。
- “无分类”：显示当前平铺专辑列表。
- 选择单个艺术家：只显示该艺术家的专辑，继续支持繁简名称兼容搜索。

默认分组视图规则：

- 艺术家分组按该艺术家的专辑数量降序排列。
- 专辑数量相同时按归一化后的艺术家显示名称升序排列，保证顺序稳定。
- 分组标题显示 `艺术家名称 · N 张专辑`。
- 合作专辑沿用当前数据语义，同时出现在所有相关艺术家的分组中。
- 不增加折叠状态，也不新增独立持久化文件。

现有“标题 / 作品数量”排序和升降序按钮只作用于每个分组内部：

- 标题：按专辑名称排序。
- 作品数量：按 `Album.works.length` 排序。
- 切换排序后，所有可见分组使用相同的组内排序规则。
- 艺术家分组本身始终保持“专辑数量降序、名称升序兜底”，不受组内排序按钮影响。

分组列表应使用惰性构建的 Flutter 滚动组件，避免一次性创建所有专辑组件。无分类和单艺术家视图继续复用现有专辑卡片、内容视图和导航行为。

### 3. 听歌报告纵向柱状图

歌曲、歌手和专辑分别显示一个 Top 10 纵向柱状图。最近播放 20 条保持现有列表形式。

数据规则：

- 每个分类按累计听歌时长降序取 Top 10。
- 累计时长相同时，依次按播放次数降序和名称升序排序。
- 柱高使用 `当前项累计时长 / 当前分类最大累计时长` 归一化；最高项满高。
- 纵轴显示格式化后的时间刻度，刻度范围从零到当前分类最大累计时长。
- 横轴显示歌曲、歌手或专辑名称。

视觉与交互：

- 每根柱顶部显示现有封面。
- 歌曲使用歌曲专辑封面，歌手使用代表作品封面，专辑使用专辑封面。
- 无封面或读取失败时回退到 Coriander Player Logo。
- 柱子保持可读的最小宽度；窄窗口通过横向滚动查看，不压缩成过细柱形。
- 名称过长时截断并通过 Tooltip 展示完整名称。
- 点击封面或柱体进入相应详情页，不触发播放。
- 空数据仍显示现有空状态，不绘制空坐标轴。

图表使用 Flutter 原生布局和绘制能力实现，不引入第三方图表依赖。

### 4. 独占模式事务式切换与自动回退

不加入 `BASS_WASAPI_AUTOFORMAT` 或 BASSmix。设备支持当前音频格式时使用原格式独占输出；不支持时恢复共享模式。

切换前记录：

- 当前文件路径。
- 当前播放位置。
- DSP 音量。
- 当前是播放、暂停还是尚未加载。
- 实际输出模式。

启用独占模式流程：

1. 捕获上述播放快照。
2. 创建独占解码流并初始化 WASAPI。
3. 恢复音量和位置。
4. 原来正在播放时启动；原来暂停时保持暂停。
5. 全部成功后才发布 `Excl` 界面状态。

独占初始化失败时：

1. 清理可能部分初始化的 WASAPI 状态和失败解码流。
2. 把实际模式恢复为共享模式。
3. 使用同一文件重新创建普通播放流。
4. 恢复音量、位置和播放/暂停状态。
5. 共享恢复成功后发布 `Shrd` 状态，并显示中文提示。

错误提示：

- 格式不支持：`当前歌曲的音频格式不受此设备的独占模式支持，已切换到共享模式。`
- 设备被占用、权限不足或驱动不支持：显示对应中文原因并说明已恢复共享模式。
- 只有共享恢复也失败时才显示无法继续播放的错误；日志保留原始异常和恢复异常。

关闭独占模式同样保留播放快照，释放 WASAPI 后重建共享流，并恢复原播放/暂停状态。

独占状态通知必须以底层实际模式为准。用户点击不等于切换成功，界面不能提前显示 `Excl`。

## 代码边界

- 爱心文案留在 `NowPlayingFavoriteButton`。
- 专辑分组和排序规则提取为可独立测试的纯 Dart 数据转换函数；页面只负责选择模式和渲染分组。
- 听歌报告聚合层负责按累计时长生成 Top 10；页面图表组件只负责比例、刻度、封面和导航。
- 独占模式的播放快照、尝试、清理和回退顺序提取为可注入操作的协调单元；`BassPlayer` 提供实际 BASS/WASAPI 操作，`PlaybackService` 只发布最终状态。
- 底层音频层不直接向界面暴露英文 `FormatException`。

## 失败与兼容策略

- 专辑没有艺术家关系时，在无分类视图中仍可访问；分组视图不猜测艺术家。
- 合作专辑允许跨艺术家分组重复，避免改变现有筛选语义。
- 报告缺少元数据时保留文字排名和 Logo，但不可导航。
- 封面读取失败只影响图片，不影响柱状图和报告数据。
- 独占失败不得破坏共享播放流；共享恢复失败时不得谎报已经恢复。
- 不删除或迁移任何用户数据。
- 不安装本机 Rust/Cargo 或大型 SDK。

## 测试与验证

所有生产改动遵循定向 TDD，先观察相应测试因缺少新行为而失败，再实现最小代码。

### 爱心

- 未收藏和已收藏状态分别显示正确中文 Tooltip。
- 禁用状态和空心/实心图标行为不回归。

### 专辑分组

- 分组按专辑数量降序，数量相同按艺术家名称升序。
- 标题和作品数量排序只改变组内顺序。
- 合作专辑出现在所有相关艺术家分组。
- 无分类、单艺术家筛选和繁简名称查询保持有效。

### 听歌报告

- Top 10 按累计时长、播放次数、名称的优先级排序。
- 柱高按当前分类最大累计时长归一化。
- 时间刻度、柱顶封面、Logo 回退和窄窗口横向滚动有效。
- 点击只导航，不触发播放。
- 最近播放 20 条不回归。

### 独占模式

- 可注入的音频操作模拟独占初始化失败，验证调用顺序为“尝试独占、清理、重建共享、恢复状态”。
- 播放状态下回退后继续播放。
- 暂停状态下回退后保持暂停。
- 空播放状态切换不创建无效流。
- 共享恢复成功后实际状态为 `Shrd` 并返回中文提示。
- 共享恢复也失败时保留两层错误信息，且不报告成功。

最后只运行相关 Flutter 测试集合、一次针对 `lib` 和 `test` 的静态分析以及 `git diff --check`。Rust/Windows 构建继续由 GitHub Actions 完成。代码验证后可使用不发布 Release 的工作流构建 Windows 包，在用户的 R7000、Realtek 3.5 mm 输出和 WH-1000XM4 上用 96 kHz/24-bit 文件复测。
